# MCP server: TypeScript to Go migration

The legacy MCP server lives in `src/server/mcp` (about 9.2k lines). The Go port
lives in `backend/internal/mcp`. This file is the tool inventory and the PR plan.
Update it in every PR.

## How the port ships

- **One PR per stage.** PR 1 (this one) is the server, transport, auth,
  dispatcher, plus `whoami` and the project tools. PR 2 ports the read-only and
  free tools. PR 3 ports the billed DataForSEO tools and cuts the proxy over.
- **Never change a tool contract silently.** A tool's name, `inputSchema`,
  `outputSchema` and text/structured output stay byte-for-byte what a cached
  Claude or ChatGPT client already negotiated. A deliberate difference is
  listed in "Deliberate differences" below and in the PR body.
- **The dispatcher proxies what Go does not own yet.** Go answers `/mcp`,
  merges its own `tools/list` with the legacy app's (minus the Go-owned names),
  and forwards a `tools/call` for a legacy tool straight to the legacy `/mcp`
  with the caller's own credential. Every tool the Go server does not own keeps
  working through the proxy; it is removed from the proxy only when its Go
  handler lands.

### PR 2 implementation status

The Go registry currently owns saved keyword list/save/remove, SERP location
search, and site audit history/status/pages/delete. Audit delete enforces the
owner/admin project-delete gate and uses the Go audit service's workflow cleanup.
Search Console, GA4, report/template/sharing, rank-tracker reads, and audit issue
formatting still use the TypeScript fallback because their public contract has
not yet been ported to Go. Keep the fallback until each corresponding Go handler
has a contract test.

## Auth and gates (legacy)

- A request reaches a tool through one of: an **API key** (`oseo_` prefix,
  verified by better-auth's `verifyApiKey`), an **OAuth grant** minted by
  `@cloudflare/workers-oauth-provider`, or a self-host/Cloudflare-Access
  identity. All become a `seomarineAuth` props object.
- `orgScope` is `"pinned"` (self-host, SAM: one org) or `"user"` (hosted OAuth
  tokens and API keys: the caller's membership in the project's org is the
  boundary).
- Project-scoped tools call `withMcpProjectAuth`: user scope derives the org
  from the project row and checks a member row (one `FORBIDDEN` for both
  unknown-project and no-membership); pinned scope checks the project against
  the token's org.
- `create_project` and `delete_site_audit` also call `requireOrgPermission`
  (`project:create` / `project:delete`, owner/admin).
- Credits are Autumn balances. Billed tools reserve/hold/settle credits and
  throw `INSUFFICIENT_CREDITS`; `run_rank_tracker` also needs a paid plan on
  hosted. Go billing is Razorpay (`billing.Service.HasPaidPlan`).

  `internal/audit`; the paid-plan and credit gates; proxy cutover where
  complete.

## Deliberate differences (must be reviewed)

- Legacy OAuth grants and access tokens live in Cloudflare KV
  (`workers-oauth-provider`), which a Go server cannot read. The Go OAuth
  provider stores its own grants in Postgres `go_mcp_oauth_*` tables. Existing
  **API keys keep working** (same `apikey` table, same SHA-256/base64url hash);
  existing **OAuth clients re-authorize once** against the Go provider. See
  `docs/maintainers/mcp-auth-design.md` (PR 1).
- Legacy rate limiting uses a Cloudflare rate-limit binding (per-colo,
  best-effort). Go uses Redis so the limit holds across instances.
